# Features

Numbered register of every feature; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md); the guard `tests/docs-contract.sh` fails when a feature has no test.

- **F1 — Base image for scheduled jobs.** An image derived from `mwaeckerlin/cron` installs the programs its jobs call in a build stage, copies them with their libraries onto the cron image and adds its schedule; the cron image itself brings no shell and no tools. The project's demo image is such a derived image.
- **F2 — Crontab files in `/etc/cron.d`.** Every file there is a crontab in the standard syntax: five time fields (minute, hour, day of month, month, day of week) with lists, ranges, steps, month and weekday names, weekday `0` and `7` for Sunday, and day of month OR day of week when both are restricted; or one of `@reboot`, `@yearly`, `@annually`, `@monthly`, `@weekly`, `@daily`, `@midnight`, `@hourly`. A file whose name holds anything but letters, digits, `_` and `-` is ignored, and the log says so.
- **F3 — Periodic directories.** Every executable file in `/etc/periodic/min`, `5min`, `10min`, `15min`, `30min`, `hourly` (minute 0), `daily` (02:00), `weekly` (Saturday 03:00), `monthly` (1st, 05:00) and `yearly` (1 January, 01:00) runs at that interval, one after the other in name order; file names follow the rule of F2.
- **F4 — Commands run without a shell.** A command line is split into arguments, with `"double"` and `'single'` quotes and backslash escapes, and the program is executed directly, found by its path or in `PATH`. Unquoted shell syntax (`|`, `&`, `;`, `<`, `>`, a `$` that is not `${NAME}` of F12, backtick, parentheses) is refused with a message, because nothing would interpret it.
- **F5 — Environment for the jobs.** A job gets the environment of the container, plus every `NAME=value` line that stands above it in the same crontab file.
- **F6 — Job output in the container log.** Output and error output of every job go to the container log, below a header that names the file, the line and the command; when the output of two jobs alternates, the header is repeated.
- **F7 — Job status in the log.** A job that fails is always logged with its exit status or signal and its duration; with `CRON_DEBUG` at `1` or higher, every start and every end is logged as well.
- **F8 — Configuration check.** At start, every crontab is checked: a wrong field, shell syntax, an unclosed quote, a program that is missing or not executable, or a date that never occurs stops the start, with file, line and cause of every error. `cron --check` runs the same check without starting and prints each job's next run, after a given time with `--at`.
- **F9 — Time zone.** Schedules follow `TZ`; without it they are in UTC.
- **F10 — Clean stop.** On stop the container ends at once with status 0, running jobs included.
- **F11 — Headless minimal production image.** Below 1MB, no shell and no interpreter to pivot with, runs and runs its jobs as an unprivileged user; `/tmp` and `/var/tmp` are writable for jobs.
- **F12 — Environment variables in crontab lines.** Before a line is parsed, every `${NAME}` in it is replaced by that variable of the container environment, in the time fields as in the command, so a derived image sets its schedule and its options with `ENV` defaults that a deployment overrides. The value is split into arguments like the rest of the line and reaches no shell. A variable that is not set, a name that is no variable name, or an unclosed `${` stops the start with file, line and cause; `cron --check` shows the lines with the values filled in.
